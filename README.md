# Shrimp Bot 🦐

Пульт сервера в Telegram: Dokploy, метрики Linux, VPN, бэкапы, Minecraft Java Edition и Home Assistant. Бот работает через long polling, публичные порты и webhook не требуются. Прежний текстовый эхо-обработчик заменён командами.

## Команды

| Команда | Возможности |
| --- | --- |
| `/status` | CPU, RAM и диск хоста по SSH; последние статусы деплоев Dokploy; HTTP-проверки из `HEALTH_URLS` |
| `/apps` | Приложения и Compose-проекты с пагинацией; кнопки логов, перезапуска и деплоя |
| `/logs immich` | Последние логи приложения или до четырёх контейнеров Compose-проекта |
| `/vpn` | Доступ к Telegram из бота и с хоста; наличие интерфейса `tg-vpn` |
| `/backups` | Последний успешный запуск каждого настроенного бэкапа и его свежесть |
| `/backups run имя` | Ручной запуск существующего задания бэкапа после подтверждения |
| `/minecraft` | Доступность Java-сервера, версия, число игроков и задержка |
| `/home` | Настроенные датчики и кнопки домашних сценариев |
| `/home run scene.evening` | Запуск разрешённой сцены или скрипта после подтверждения |
| `/whoami` | ID отправителя, чата и темы для настройки доступа |
| `/start`, `/help` | Справка |

Сервисы можно выбирать по уникальному имени, имени проекта, `проект/сервис` или полному пути `проект/окружение/сервис`. При неоднозначном имени бот попросит полный путь. Например, `/logs immich` выбирает единственный сервис проекта Immich.

Статус `done` в Dokploy означает завершённый деплой, а не работоспособность приложения. Для проверки HTTP-доступности добавьте адреса в `HEALTH_URLS`. Интерфейс VPN и ответ Telegram проверяются отдельно; это не доказательство маршрута конкретного соединения.

## Локальный запуск

Нужен Python 3.10+ и `ssh` для метрик хоста. На этом компьютере доступен `python3.11`.

```bash
cd /Users/andrejstrelcenko/Desktop/strand.moscow/shrimp-bot
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Только если .env ещё нет; существующий файл с токеном не заменяйте.
cp -n .env.example .env
python bot.py
```

Переменные окружения имеют приоритет над `.env`. Токены не нужно вписывать в Python-код. Для одного токена запускайте один экземпляр; если бот уже работает в Dokploy, не запускайте параллельно локальный polling с тем же токеном.

## Первичная настройка доступа

1. Задайте `BOT_TOKEN`, отправьте боту `/whoami`.
2. Добавьте свой числовой **user ID** в `ALLOWED_USER_IDS`. Это не ID группы и не ID бота.
3. При необходимости ограничьте чаты через `ALLOWED_CHAT_IDS`. В примере задана группа `-1002526628474`. Добавьте ID личного чата или очистите список, если хотите использовать команды лично.
4. Перезапустите бота после изменения настроек.

Без `ALLOWED_USER_IDS` все команды сервера закрыты, включая просмотр логов. Справка и `/whoami` доступны для первичной настройки. Членство в группе не даёт прав управления. Кнопка привязана к отправителю, чату и сообщению; подтверждение действительно 120 секунд и принимается один раз. После отмены подтвердить старое действие нельзя. После перезапуска старые кнопки недействительны.

## Настройки интеграций

Все переменные и примеры находятся в `.env.example`. Можно подключать интеграции постепенно: отсутствие ключа одной интеграции не мешает другим командам.

### Dokploy

```dotenv
DOKPLOY_URL=https://dokploy.strand.moscow
DOKPLOY_API_KEY=ваш_ключ
HEALTH_URLS='{"immich":"https://photos.example.com","home":"http://192.168.0.70:8123"}'
```

API-ключ создаётся в профиле Dokploy, раздел API/CLI. Бот использует REST API с заголовком `x-api-key`; MCP-соединение из Codex автоматически ему не передаётся. Права ключа определяют доступные проекты и действия.

Перезапуск Application использует `application.reload` без пересборки. Перезапуск Compose выполняет `compose.stop`, затем `compose.start` и временно прерывает работу всего проекта. Деплой использует текущий источник, настроенный в Dokploy. После принятия запроса API бот не выдаёт его за завершённый деплой: результат виден в Dokploy и `/apps`.

Логи сокращаются до размера сообщения Telegram. Маскируются известные токены бота, Dokploy и HA, а также распространённые записи паролей и ключей. Произвольные секреты в нестандартном формате могут остаться в исходных логах — не выводите их в приложениях.

### Метрики Linux и VPN

```dotenv
SERVER_SSH_HOST=192.168.0.70
SERVER_SSH_USER=alex
SERVER_SSH_PORT=22
SERVER_SSH_KEY_FILE=/run/secrets/server_key
SERVER_SSH_KNOWN_HOSTS_FILE=/run/secrets/known_hosts
SERVER_DISK_PATH=/
VPN_INTERFACE=tg-vpn
```

Нужен SSH-доступ **из контейнера бота**, отдельный ключ и Python 3 на целевом Linux-хосте. Из внешней сети вместо `192.168.0.70` можно использовать `109.94.1.253`. Секретные файлы монтируются в контейнер read-only по путям из настроек; в Git их добавлять не нужно. Пользователь контейнера должен иметь право их читать.

В `known_hosts` заранее сохраните проверенный ключ сервера. Проверка ключа обязательна; неизвестный или изменившийся ключ отклоняется. Если SSH уже настроен для пользователя, пути можно не задавать — используются стандартные настройки SSH.

Бот отправляет по SSH только исходник `scripts/server_probe.py` с фиксированными режимами `status` и `vpn`. Root, Docker socket и произвольный ввод shell-команд из Telegram не нужны. CPU/RAM/диск читаются на хосте, а не внутри контейнера бота.

### Бэкапы

Сначала создайте задания в Dokploy. Затем перечислите их ID:

```dotenv
BACKUP_TARGETS='[{"name":"immich-db","id":"BACKUP_ID","kind":"backup","max_age_hours":26},{"name":"photos","id":"VOLUME_BACKUP_ID","kind":"volumeBackup","max_age_hours":168}]'
```

`backup` — задание БД или Compose; `volumeBackup` — задание тома. Команда проверяет историю `deployment.allByType`, выбирает последний успешный запуск с известным временем завершения и предупреждает, если он старше `max_age_hours`, отсутствует или последний запуск завершился ошибкой. Это не проверяет существование и восстановимость файлов в хранилище.

Для автоматических предупреждений:

```dotenv
BACKUP_ALERT_CHAT_ID=-1002526628474
BACKUP_CHECK_SECONDS=3600
# Если нужна конкретная тема форума:
BACKUP_ALERT_THREAD_ID=
```

Пустой `BACKUP_ALERT_CHAT_ID` выключает фоновые проверки. Оповещения приходят при проблеме, изменении состояния и восстановлении; при неизменном состоянии бот молчит. Состояние дедупликации хранится в памяти: после перезапуска первая проверка может повторно сообщить о текущей проблеме. Время в отчётах — UTC. Бот не создаёт новые задания бэкапа и не меняет их расписание.

### Minecraft

```dotenv
MINECRAFT_HOST=192.168.0.70
MINECRAFT_PORT=25565
```

Поддерживается Java Edition через Server List Ping. В `server.properties` должен быть включён `enable-status=true`; RCON для чтения статуса не нужен. Адрес должен быть доступен из контейнера бота. Bedrock этим клиентом не поддерживается.

### Home Assistant

```dotenv
HA_URL=http://192.168.0.70:8123
HA_TOKEN=long_lived_access_token
HA_ENTITIES=sensor.temperature,binary_sensor.door
HA_SCENES=scene.evening,script.close_house
```

Long-Lived Access Token создаётся в профиле Home Assistant, раздел безопасности. Бот читает только перечисленные датчики и запускает только перечисленные `scene.*` / `script.*`. Сценарии выполняются через `turn_on` после подтверждения. Произвольный вызов сервисов HA из Telegram не разрешён.

## Сборка и Dokploy

В репозитории есть два варианта сборки:

- Текущий **Nixpacks**: `nixpacks.toml` добавляет OpenSSH и задаёт команду `python bot.py`. Оставьте поле переопределения команды Dokploy пустым, чтобы использовалось виртуальное окружение Nixpacks.
- **Dockerfile**: Python 3.11, OpenSSH, запуск от пользователя `bot` (UID 10001). В Dokploy выберите Build Type → Dockerfile. Токены задавайте только в runtime Environment; Dockerfile не копирует `.env` и SSH-ключи в образ.

После пуша заполните Environment приложения в Dokploy: как минимум `BOT_TOKEN`, `ALLOWED_USER_IDS` и ключи нужных интеграций. Локальный `.env` не попадёт на сервер через Git. Для SSH дополнительно настройте read-only mounts ключа и `known_hosts`.

Сохраняйте одну реплику и обновление `stop-first`. В первой настройке этого приложения `Auto Deploy` был выключен: для запуска от пуша его нужно включить и подключить GitHub webhook / GitHub provider в Dokploy. Одного пуша в GitHub без этого недостаточно.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты используют подставные API и не отправляют сообщения, не перезапускают сервисы и не обращаются к боевому серверу. Они проверяют доступ, подтверждения, API-запросы, ошибки, свежесть бэкапов и дедупликацию оповещений.

Бот на этом же сервере не сможет оповестить о полном отключении хоста или Telegram/VPN. Для такой проверки нужен отдельный внешний наблюдатель.
